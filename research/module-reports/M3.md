## Implementation Evidence

### Ingestion and source fidelity

- `SourceInput` supports the three CCS-2.1 evidence modes: `CAS`,
  `GIT_IMMUTABLE`, and `EXTERNAL_IMMUTABLE`.
- Local paths are absolute, regular, non-symlink files contained by a
  repository root and represented by a literal repository-relative path.
- Git mode requires a canonical HTTPS repository identity, a full algorithm-
  tagged commit OID, a matching local `origin`, and bytes equal to
  `git show <commit>:<path>`. No network fetch is attempted.
- External mode accepts an offline byte fixture plus a canonical HTTPS, DOI, or
  URN locator, independent content digest, source, and verification method. It
  does not silently fall back to CAS.
- Snapshots retain exact UTF-8 bytes, content digest, capture metadata,
  repository/commit/path or external locator, parser kind, and the requesting
  principal. Snapshot identity excludes capture time so repeated identical
  inputs receive the same ID.
- Strict JSON rejects duplicate keys and non-finite constants. Strict YAML
  rejects duplicate keys, aliases, anchors, and tags. Invalid UTF-8 and lone
  surrogates fail closed.

### Deterministic atomization and source-map

- Markdown headings and bodies are parsed without an LLM; Python symbols use
  `ast`; configuration keys use strict JSON/YAML parsing; other sources use
  stable non-empty line spans.
- Candidate IDs are derived from snapshot ID, statement, kind, exact line
  span, and stable symbol/heading. Repeated extraction is deterministic.
- Every candidate is registered in the quarantine store and carries a private
  extractor token. Generated candidates (`generated=True`) are always `T3` and
  `candidate`; ordinary deterministic source candidates are classified `T2`
  and remain candidates until approval.
- Evidence bindings include mode, content/blob digest, span digest, media type,
  access policy, source snapshot, and stable source-map fields. Git bindings
  include repository URI, full immutable commit, path, symbol/heading, and
  line span. Binding and render operations recheck source bytes and span
  digests, so retaining an old line number cannot hide source drift.

### Quarantine and promotion

- The append-only process-local store accepts snapshots and candidates only from
  ingestion/extraction capabilities; callers cannot register an arbitrary
  object through the public constructors alone.
- Promotion is fail-closed when evidence is missing, the candidate or binding
  digest does not match, the source has drifted, the approval is rejected,
  forged, expired, future-dated, self-issued, or not verified by the injected
  trusted authority.
- A successful promotion emits an immutable `ValidatedAtom` with final trust
  `T1`, status `validated`, exact evidence bindings, and the matching approval.
- The approval implementation is an injectable HMAC test/research adapter. It
  is explicitly not a production signature-security claim; the default store
  has no implicit signing authority and denies approval.
- Secret detection runs before snapshot/CAS persistence, binding, promotion,
  package writing, and evidence rendering. Detection failures block the path.

### Build, validation, and publication boundary

- `build_capsule` accepts only store-emitted `ValidatedAtom` values and
  revalidates each one through the same store before constructing the seven
  CCS-2.1 modules. Raw candidates and forged/replaced validated values are
  rejected.
- The builder emits source-map and approval metadata as extension data while
  preserving the M2 core model. It does not resolve eligibility, rank, compute
  dependency closure, resolve conflicts, compile a view, activate a version,
  or roll back a version.
- A temporary package is written, checked by the public M2 `load_capsule`
  entry point (strict parsing, Schema, Python semantics, digest and reference
  integrity), and only then returned as a `DraftCapsule`.
- `publish_draft` requires the private loader receipt and delegates to M2
  `Registry.publish`, retaining M2 lifecycle, CAS, authorization, immutable
  version, and transaction semantics. There is no internal publication
  bypass.
