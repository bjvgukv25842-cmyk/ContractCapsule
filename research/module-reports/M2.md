All models reject unknown fields, coercive input, non-finite values, malformed
digests/versions/dates, unsafe security paths, invalid modes, unresolved or
non-reciprocal Evidence bindings, duplicate identities, and inconsistent
signature metadata. Tuples and recursively frozen mappings prevent in-place
mutation. Registry publication re-enters the strict validation boundary so a
Pydantic `model_copy(update=...)` cannot bypass publication invariants.

The eight static documents are generated deterministically from the model
definitions and compared byte-semantically in tests. The authoritative
`validate_capsule_document` entry point applies Draft 2020-12 structure first
and the mandatory Python semantic pass second. Generic JSON Schema engines
cannot express every cross-record identity/reference relation; the root Schema
declares the semantic entry point with
`x-contractcapsule-semantic-validation`. This limitation is not hidden or
reported as raw-Schema equivalence.

## CCS-2.1-canonical-v1 Identity Projection

The implementation builds an explicit whitelist projection. It does not dump
the whole Capsule and remove fields afterward.

| Module | Included paths |
|---|---|
| Projection root | `profile` fixed to `CCS-2.1-canonical-v1` |
| Control Manifest | spec/profile, ID/version, owner/tenant, all scope arrays, authority, sensitivity, provides/requires/conflicts, lifecycle, created-from, integrity lock/signature references, extensions |
| Semantic Payload | module extensions; every ordered Atom field including validity, authority, status, confidence, evidence/dependency/conflict references, sensitivity, compression class, refresh policy, extensions |
| Evidence Plane | module extensions; every ordered common Evidence field including digest, media type, captured time, retention, access policy and validation; complete Git locator fields; complete external source/verification fields |
| Dependency Graph | module extensions and every ordered edge field, version constraint, mandatory bit, and edge extensions |
| Replacement Contract | identity/replaces, preconditions, effects, protected invariants, allowed/forbidden scope, all verification commands, activation policy, rollback policy, extensions |
| Compression Policy | version, ordered P0-P4 class fields and expansion/TTL rules, extensions |
| Tests & Integrity | ordered tests and checksums, complete dependency/source/compiler/adapter/policy/test/model/parameter/runtime lock fields, signature policy, extensions |

Exact included leaf paths are enumerated in M2-003 of
`research/decision-log.md`. Explicit exclusions are:

- `control_manifest.content_digest` and any other repeated root digest;
- detached-signature transport fields, including value and envelope; normative
  signature algorithm/key/profile remain identity-bound in signature policy;
- package-byte digest, which M2 does not expose;
- `derived_artifacts.*`, including Embeddings, cache, indexes, and Compiled
  Views;
- `runtime_sidecar.*`, including logs, observations, and runtime timestamps.

JCS/RFC 8785 serialization uses UTF-8, recursive key ordering, no insignificant
whitespace, and no Unicode normalization. Array order is retained and is
identity-relevant under the author's canonical-v1 rule. Non-string object
keys, lone surrogates, duplicate input keys, unsafe integers, NaN, and
infinities fail closed. The result format is exactly `sha256:` plus 64
lowercase hexadecimal characters. Future signing input is frozen as
`b"CCS-2.1-signature-v1\0" + content_digest.encode("ascii")`; no signing or
production signature-security result is claimed.

M1's `repr()` digest remains a decision witness only. M1's mathematical set
notation represents semantic membership; canonical-v1 uses the author-approved
ordered transport representation because CCS-2.1 does not freeze a unique sort
key for these arrays.

## Package Loader Trust Boundary

Required frozen carriers are parsed with strict UTF-8, duplicate-key rejection,
finite/exact numeric checks, and safe YAML restrictions. The two optional
metadata carriers hold only module-level extension objects; they preserve
canonical-v1 extensions without becoming new core modules and may be absent
when empty.

The loader rejects:

- missing core carriers or safety-critical fields;
- unknown carrier keys, files, modes, or cross-mode fields;
- duplicate logical/case-folded files and duplicate JSON/YAML keys;
- YAML aliases, anchors, tags, and non-JSON values;
- invalid UTF-8, lone surrogates, NaN, Infinity, and unsafe integers;
- absolute, drive-qualified, non-literal, traversal, or backslash paths;
- root, directory, file, or bundled-blob symlinks and non-regular entries;
- incomplete or contradictory Atom/Evidence references;
- missing or mismatched test artifacts and CAS Evidence bytes;
- malformed Git commit OIDs or unsafe repository-relative paths;
- noncanonical HTTPS/persistent identifiers;
- declared/core digest mismatch.

`CAS` records require locally bundled and rehashed bytes. `GIT_IMMUTABLE`
records require canonical repository identity, algorithm-tagged full OID,
literal relative path, locator digest, Evidence digest, and media type.
`EXTERNAL_IMMUTABLE` records require a canonical HTTPS/DOI/URN locator,
Evidence digest, media type, source, and verification method. The latter two
modes perform no network fetch and never fall back to CAS.

No partial Capsule is returned and loading performs no persistent write.
Callers must supply a stable local package snapshot: M2 rejects static
symlinks and traversal but does not claim containment of a separate hostile
process concurrently replacing directory entries during a load.

## Filesystem CAS Semantics

- Payload SHA-256 selects `objects/sha256/<2>/<62>.blob`.
- A single canonical envelope stores digest, media type, size, and bytes.
- Temporary and final entries share a filesystem directory.
- The complete temporary envelope is flushed and file-synced before
  no-replace hard-link publication; the containing directory is then synced.
- Per-digest advisory locks serialize reads and writes across processes, so a
  failed post-link durability check cannot be observed as a successful object
  by a concurrent operation.
- Existing objects are fully rehashed and their media type is compared; no
  public overwrite or deletion operation exists.
- Static symlinked internal directories and digest prefixes fail closed.
- Writes grant no read access. Direct reads default deny and require an exact
  trusted Boolean authorization result.

The plan's shorthand “atomic rename” was realized with an atomic no-replace
hard link because ordinary replace/rename semantics could overwrite an
existing immutable object. This is a safety-preserving implementation choice,
not a weakening of the plan.

## SQLite Registry Semantics

| Table | Key/invariant | Stored facts |
|---|---|---|
| `publications` | unique `(capsule_id, version)` | digest, lifecycle, authority, scope JCS, immutable core JCS, detached transport record, original timestamp |
| `evidence_references` | primary `(publication_id, evidence_id)` and unique ordinal | mode, digest, media type, access policy, immutable Evidence JCS |
| `digest_grants` | primary `(publication_id, evidence_id, digest)` and foreign key to Evidence | published-reference read grant constraint |

`publish()` strictly revalidates the candidate, validates PUBLISHED lifecycle
without mutating it, resolves publish permission, starts `BEGIN IMMEDIATE`,
then privately rehashes referenced CAS bytes and media type before inserting
publication, Evidence, and grants in one SQLite transaction. Any failure rolls
back Registry state. A successful earlier CAS write may remain as an unreadable
orphan because SQLite and the filesystem cannot form one transaction.

Trusted Policy Resolver decisions are test-injectable and default deny.
Malformed/truthy results deny. Effective permission is Resolver permission
intersected with Capsule access policies; those declarations can only narrow.
`get_blob()` uses the union of independently valid published references and
revalidates the full publication, Evidence row, grant, CAS digest, CAS media
type, and bytes before returning data.

Exact republish reauthorizes and compares every immutable publication,
signature, Evidence, and grant field. It returns the original row and
timestamp without a write. Same ID/version with another digest raises a
version conflict; another immutable difference raises a publication conflict.
There is no `INSERT OR REPLACE`, `REPLACE INTO`, update, delete, activity
pointer, activation, or rollback API.

## Known Limits, Deviations, and Risks

- Early start is an author-approved six-day schedule deviation.
- Static JSON Schema is structural; mandatory Python semantic validation is
  required for cross-record constraints and is explicitly declared.
- Optional extension metadata carriers are a canonical-v1 transport mapping,
  not extra core modules. Frozen-structure packages with empty module
  extensions do not require them.
- Package loading assumes a stable local snapshot against concurrent directory
  replacement; static symlinks and traversal are rejected.
- Advisory digest locks and no-replace links target POSIX local filesystems;
  distributed/network filesystem semantics are not claimed.
- SQLite and filesystem CAS do not provide one cross-resource transaction;
  unreadable orphan blobs are permitted and no garbage collector is in M2.
- One repository/authority trust domain only; no cross-tenant isolation,
  revocation, dynamic role inheritance, distributed authorization, or
  Registry consensus.
- Signature structure and future signing input are frozen, but M2 performs no
  cryptographic verification and makes no production signature-security claim.
- No package-byte digest is exposed because the container byte format is not
  frozen.
- Registry intentionally drops B/C sidecars on publication; they remain
  reconstructible/non-factual and do not affect identity.
- M1's set notation is adapted to the author's ordered-array canonical-v1
  decision; no M1 behavior test changed.
